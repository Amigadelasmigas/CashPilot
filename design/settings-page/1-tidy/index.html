Learn more about device ids

An id stays here after you remove its service. Use it to find the device at the provider, or give a new box the same id.

  • Every Show and Copy is written to the audit log.
  • Passwords, keys and wallet seeds are never kept here.
  • Change gives a box a new id. Add an id keeps an id CashPilot did not deploy with.
  • Download all asks for your password, because the file holds every id in full.

Restore from a backup

Put a Mysterium, ProxyBase or Anyone identity back from a .cpbackup file. It only makes a new container. It never writes over a running one.

Learn more about restore

The file must be made with a passphrase. The box you pick must not run the service already.

To replace a running identity: download its backup first. Then remove the service from that box on the dashboard, and say yes when it asks to delete its data. Then restore here.

Files sealed to a key, Storj and Sia use the command line steps.

How to turn on file mode
  1. Add this line to the worker on the boxIn the worker's compose file, under environment: 
    services:
  cashpilot-worker:
    environment:
      - CASHPILOT_EARNER_SECRETS=file
  2. Recreate the worker containerSo it reads the new line: 
    docker compose up -d cashpilot-worker
  3. Redeploy each earner on that boxOpen the earner on the dashboard and press Redeploy. This table then counts it under "In a file".

To undo: remove the line, then do steps 2 and 3 again. The next redeploy puts the passwords back in the container settings.

Learn more about earner credentials

Container settings are what Docker stores for each container: its environment and command line. docker inspect, a backup of Docker's folder and any tool with the Docker socket show them in plain text.

File mode (CASHPILOT_EARNER_SECRETS=file) gives each earner its passwords in a file that only the earner reads. Root on that box can still read the file, so this is not a wall against root.

It covers Bitping, Earn.fm, Honeygain, IPRoyal Pawns, ProxyBase, ProxyRack, Repocket, Traffmonetizer, URnetwork and Sia hostd. Custom services and Sia's wallet seed are not covered. Read the guide.

Learn more about environment settings

Settings passed with Docker -e are locked here. You can store a value for the others, but nothing reads it back. The field stays so an old stored value does not disappear.

Some settings cannot change while CashPilot runs:

  • The session key signs the logins already in use.
  • The data directory is where the open database lives.
  • The fleet key is what enrolled workers already hold.

Credential encryption key

One key decrypts every credential CashPilot stores. Keep it outside the data folder.

In the data folder

The key is in the data folder (/data/.fernet_key). A copy of that folder can decrypt every stored credential.

  1. Show the key and copy itCashPilot asks for your password first and writes the reveal to the audit log.
    Key copied. Paste it into your secret store, then clear your clipboard.
  2. Save it in a file outside the data folderThe UI runs as user 1000, so that user must be able to read the file. With Docker Compose, put it in ./secrets/cashpilot_encryption_key: 
    mkdir -p secrets
sudo chown 1000:1000 secrets/cashpilot_encryption_key
sudo chmod 400 secrets/cashpilot_encryption_key
    Then add the secret to your compose file: 
    secrets:
  cashpilot_encryption_key:
    file: ./secrets/cashpilot_encryption_key

services:
  cashpilot-ui:
    secrets:
      - cashpilot_encryption_key
    environment:
      - CASHPILOT_ENCRYPTION_KEY_FILE=/run/secrets/cashpilot_encryption_key
    A secret manager works too. The guide has steps for Infisical, Vault, 1Password and Bitwarden.
  3. Recreate the UI containerSo it reads the new setting: 
    docker compose up -d cashpilot-ui
  4. Come back to this pageIt checks that the key now comes from outside the data folder, then offers to delete the copy that is still there.
