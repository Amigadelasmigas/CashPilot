Security

Earner credentials on each box

Not protected

Keep earner passwords out of Docker's container settings. You turn this on for each box.

  • Docker keeps each container's settings in plain text. docker inspect, a backup of Docker's folder and any tool with the Docker socket can read every earner password there.
  • With CASHPILOT_EARNER_SECRETS=file on a worker, each earner reads its password from a file. Only that earner can read the file.
  • Root on the box can still read the file. This does not protect against root.
  • Some earners are not covered. The guide lists them.

Protect the earners on a box

Do this on each box.
  1. Add this line to the worker's environment.
    CASHPILOT_EARNER_SECRETS=file
  2. Recreate the worker container.
    docker compose up -d cashpilot-worker
  3. Redeploy each earner on that box.
    Use Redeploy on the dashboard. This page then shows the box as protected.

Undo: remove the line, recreate the worker and redeploy. The passwords go back into container settings.

Credential encryption key

In the data folder

One key decrypts every credential CashPilot stores. Keep it outside the data folder.

On a default install, the key is in the data folder, next to the database it decrypts. Anyone with a copy of that folder can then read your credentials. When the key is outside the folder, a copy of the folder alone is not enough.

Move and restore

Restore from a backup

Put back a Mysterium, ProxyBase or Anyone identity from a .cpbackup file.

  • The file must be one made with a passphrase.
  • A restore only creates a new container, on a box that does not run the service. It never writes over a running one.
  • To replace a running identity: download its backup first. Then remove the service from that box on the dashboard, and say yes when it asks to delete its data. Then restore here.
  • Files sealed to a key, Storj and Sia use the command line steps.
CashPilot checks the file before anything changes.

Bring your services over from money4band, CashFactory or InternetIncome.

  • CashPilot does not run or fetch anything in the files, and it does not keep the files.
  • Guides for each tool: money4band, CashFactory, InternetIncome.

About and updates

Up to date

CashPilot checks GitHub for the newest release, and can update itself.

  • The update button runs docker compose pull && docker compose up -d for you, from a one-shot helper container.
  • It installs the newest patch of the image series your compose file pins.
  • To move to a newer series, edit the image tags. Read UPGRADING.md first. Update the UI host first, then every worker.
  • An install not managed by Compose gets the manual commands instead.

    Zm9vYmFyLWRlbW8ta2V5LW5vdC1yZWFsLTAwMDAwMDA=

    Key copied. Paste it into your secret store, then clear your clipboard.

  2. Save it in a file outside the data folder.
    The UI runs as user 1000, so that user must be able to read it.
    mkdir -p secrets
sudo chown 1000:1000 secrets/cashpilot_encryption_key
sudo chmod 400 secrets/cashpilot_encryption_key
    Add it to your compose file 
    secrets:
  cashpilot_encryption_key:
    file: ./secrets/cashpilot_encryption_key
services:
  cashpilot-ui:
    secrets:
      - cashpilot_encryption_key
    environment:
      - CASHPILOT_ENCRYPTION_KEY_FILE=/run/secrets/cashpilot_encryption_key
    A secret manager works too. The guide has steps for Infisical, Vault, 1Password and Bitwarden.
  3. Recreate the UI container.
    docker compose up -d cashpilot-ui
  4. Come back to this page.
    It checks where the key comes from, then offers to delete the copy in the data folder.
