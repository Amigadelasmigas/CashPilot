Earner credentials on each box

0 of 5 boxes protected·23 earners keep their passwords in Docker settings

How to turn it on

Docker shows an earner's password in plain text to anyone who can read its settings. In file mode, the password goes in a file that only the earner reads.

Learn more

Docker settings are the environment and command line Docker keeps for each container. docker inspect, a backup of Docker's folder and any tool with the Docker socket can read them.

File mode is the worker setting CASHPILOT_EARNER_SECRETS=file. Root on the box can still read the file, so it does not stop root.

It covers Bitping, Earn.fm, Honeygain, IPRoyal Pawns, ProxyBase, ProxyRack, Repocket, Traffmonetizer, URnetwork and Sia hostd. It does not cover custom services or Sia's wallet seed. Read the guide

How to turn on file mode on a box

  1. Add this line to the worker's environment.

    services:
  cashpilot-worker:
    environment:
      - CASHPILOT_EARNER_SECRETS=file

  2. Recreate the worker container.

    docker compose up -d cashpilot-worker

  3. Redeploy each earner.

    On the dashboard, open the service and press Redeploy. This table then counts it under "In a file".

To undo: remove the line, recreate the worker, then redeploy. The passwords go back into Docker settings.

(e) Credential encryption key · key shown and copied; then, after the move, the copy in the data folder deleted. The app has no "regenerate" action: Delete the copy is the destructive step here.

Security

Credential encryption key

In the data folder·moving it out: step 1 of 4

  1. Show the key and copy it.

    CashPilot asks for your password first. The reveal goes into the audit log.

    Key copied. Paste it into your secret store, then clear your clipboard.

  2. Save the key in a file outside the data folder.

    The UI runs as user 1000, so that user must read the file. With Compose, put it in ./secrets/cashpilot_encryption_key.

    mkdir -p secrets
sudo chown 1000:1000 secrets/cashpilot_encryption_key
sudo chmod 400 secrets/cashpilot_encryption_key

    Then add the secret to your compose file:

    secrets:
  cashpilot_encryption_key:
    file: ./secrets/cashpilot_encryption_key

services:
  cashpilot-ui:
    secrets:
      - cashpilot_encryption_key
    environment:
      - CASHPILOT_ENCRYPTION_KEY_FILE=/run/secrets/cashpilot_encryption_key
    Use a secret manager instead

    Anything that writes the key to a file, or sets CASHPILOT_ENCRYPTION_KEY, works. The guide has tested steps for Infisical, Vault, 1Password and Bitwarden.

  3. Recreate the UI container, so it reads the new setting.

    docker compose up -d cashpilot-ui

  4. Come back to this page.

    It checks that the key comes from outside the data folder. Then it offers to delete the copy that is still there.
