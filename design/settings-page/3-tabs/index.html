  • A restore makes a new container on a box that does not run the service. It never writes over a running one.

Credential encryption key

In the data folder

One key decrypts every credential CashPilot saves. Keep it outside the data folder.

The key is in the data folder (/data/.fernet_key).
A copy of that folder can decrypt every stored credential.
Why this matters
  • On a default install the key sits next to the database it decrypts.
  • So anyone with a copy of the data folder can read your credentials.
  • With the key outside the folder, a copy of the folder alone is not enough.

How to turn on file mode, and how to undo it
  1. Add this line to the worker's environment.
    Put it in the compose file on that box.
    services:
  cashpilot-worker:
    environment:
      - CASHPILOT_EARNER_SECRETS=file
  2. Recreate the worker container.
    docker compose up -d cashpilot-worker
  3. Redeploy each earner on that box.
    Open the service on the Dashboard and press Redeploy. This page counts down as each one moves to a file.

To undo: remove the line, then do steps 2 and 3 again. The next redeploy puts the passwords back in the container settings.

What file mode protects against, and what it does not
  • Without it, docker inspect, a backup of Docker's folder and any tool with the Docker socket show every earner password in plain text.
  • With it, each earner reads its password from a file that only that earner reads.
  • Root on the box can still read the file. File mode is not a wall against root.
  • It covers Bitping, Earn.fm, Honeygain, IPRoyal Pawns, ProxyBase, ProxyRack, Repocket, Traffmonetizer, URnetwork and Sia hostd. It does not cover custom services or Sia's wallet seed.

(e) Encryption key: moving it out, key shown, then deleting the copy left behind

Credential encryption key

In the data folder

One key decrypts every credential CashPilot saves. Keep it outside the data folder.

The key is in the data folder (/data/.fernet_key).
A copy of that folder can decrypt every stored credential.
  1. Show the key and copy it.
    CashPilot asks for your password first and writes the reveal to the audit log.
    toast Key copied. Paste it into your secret store, then clear your clipboard.
  2. Save the key in a file outside the data folder.
    The UI runs as user 1000, so that user must read the file. With Compose, use ./secrets/cashpilot_encryption_key.
    mkdir -p secrets
sudo chown 1000:1000 secrets/cashpilot_encryption_key
sudo chmod 400 secrets/cashpilot_encryption_key
    Then add the secret to your compose file:
    secrets:
  cashpilot_encryption_key:
    file: ./secrets/cashpilot_encryption_key

services:
  cashpilot-ui:
    secrets:
      - cashpilot_encryption_key
    environment:
      - CASHPILOT_ENCRYPTION_KEY_FILE=/run/secrets/cashpilot_encryption_key
    A secret manager works too. The guide has steps for Infisical, Vault, 1Password and Bitwarden.
  3. Recreate the UI container, so it reads the new setting.
    docker compose up -d cashpilot-ui
  4. Come back to this page.
    It checks that the key now comes from outside the data folder. Then it offers to delete the copy still there.
